# EVA、車輛、飛機、水與多星系：共同開發範圍

2026-10-07，使用者授權主 agent 管理四項功能，逐項 branch/worktree、subagent
實作，主 agent 審查、協調與必要的 TigerVNC 初步驗證。共用規則見 ../../AGENTS.md。
一般取捨由主 agent 處理；完成可驗收交付或已嘗試而無法有意義推進時才交回使用者。

## 使用者確認的範圍與優先順序

Assembly 指零件定義、PartGraph／接合與姿態接口、各模組用途、碰撞幾何及外觀。
本輪不要求 KSP VAB 類組裝 view 或組裝→Flight 前端流程；未來前端應能透過核心
接口建立／編輯／驗證／保存船，不應為加入前端而重寫物理或零件模型。
既有編輯器可以作診斷入口，但不以完成前端代替本輪物理交付。

優先驗證困難的空間／動態行為：EVA 接觸與移動、輪胎／懸吊與地形、飛機幾何與
翼面施力、海面浮力及多尺度精度。資源耗用／電力／停機門檻等規則可以後移，
不得讓這些容易做的項目佔據核心交付。保留既有火箭資源語義；新動力模型若暫未
加入資源限制，須明確記錄，不宣稱具備完整能源系統。

## 四項第一輪

- EVA／車輛：出入艙、地面步行／跳躍、背包操控、座位／上下車；可配置輪子、
  轉向／驅動／煞車／懸吊。攀爬、艙內行走、游泳不做。乘員身份、質量與控制权
  交接必须明确。主遊戲提供可直接驗收的場景與普通操作入口。
- 飛機：可組裝的機身、機翼／可控翼面、推進與起落架；外觀、collider、質量／
  慣量與作用點一致。用同一 Fleet 完成滑行、起飛、操控與降落；不採獨立 aircraft
  runtime。表面接合與姿態／鏡像接口屬共用核心，飛機与 rover 不各自另建模型。
- 水：現有海面上，零件／火箭依浸水排水量與質量受到浮力及水阻；可傾斜／翻覆／
  下沉，不強制所有零件漂浮。不做複雜流體、進水、游泳或潛艇。岸上不能誤算浮力。
- 多星系：把現有 orbit 世界擴至總共兩三個恆星系，沿用現有火箭，不增加特殊
  星際推進。維持同一船資料、各星系局部精度、跨框架與多船操作、存讀／錄放。
  不要求相對論、蟲洞或整個銀河重力求解。航程時間很長，不以傳送或特殊初速
  場景冒稱正常火箭已完成航行；驗收 fixture 明確標示。

## 主遊戲交付與 crate 邊界

各 agent 直接在所屬 branch/worktree 修改主遊戲與適當 core；不要求先做獨立
demo 視窗再接線。固定場景可作主遊戲驗收入口；lab/example 僅作必要診斷，
不能取代主遊戲交付。是否拆新 crate 由主 agent 依複雜度、耦合度與責任邊界
決定；功能邏輯不塞入 app，也不為每項功能強制建立新 crate／平行 runtime。

## 分工與接縫

四個 worktrees 起點为 a145fad：work/eva-vehicles、work/galactic-flight、
work/aircraft-assembly、work/water-physics。各功能主遊戲與 core 由所屬分支交付。
主 agent 先固定共用接口：assembly 幾何／接合、Wheel、typed 控制、乘員質量、
環境海水、跨星系精確船狀態、版本與 checkpoint／journal。共享檔案修改需協調。
Wheel 由車輛分支負責，飛機起落架共用；assembly 幾何／接合接口由飛機分支負責。
不允許從 app 直接改物理 cache 或繞過 PartGraph。

約十分鐘或在接縫／卡關／昂貴檢查時追蹤 agent。Bevy 連結與 GUI 由主 agent
排程，-j 2；TigerVNC 初步檢查必須觀察動態，不能只用靜態截圖或數值規則測試
宣稱接觸正確。配合針對性物理不變量／存讀／錄放測試。人類最終驗收仍由使用者。
各分支完成後再核對組合行為；不自動跑全 workspace。
