# 任務：零件運行狀態與多資源供應

狀態：實作與核對完成，使用者已接受目前降落傘外觀；尚未提交或合併。任務分支 `claude/part-state-resources`。
起始程式基線：`7a4e5d2`（已審查的四項重構，MODEL_VERSION 9）。
相關：[NOTE.md](../../NOTE.md)、[part-modules.md](../part-modules.md)、[part-graph.md](../part-graph.md)。

## 目標

把現有單一 fuel_kg 與零件級 lit/staged 的假設，演進成零件擁有資源存量及模組運行狀態。新增消耗者或可展開零件時，不再另開一套船表示法、資源扣除或存檔旁路。

本任務必須交付可用核心、Fleet 接線、獨立 lab、存讀檔及錄放覆蓋。用「兩種推進劑互不混用」與「降落傘展開後跨 owner／分離／合併／還原」證明設計成立；不是只增加未使用的抽象。

## 現有接口與問題

- `assembly/src/model.rs`：Module、PartDefinition、PartInstance；craft 寫單一 fuel_kg。
- `assembly/src/graph.rs`：PartGraph 為唯一 live 零件紀錄；Part 有 fuel_kg、staged、lit，Part::engine 取第一個引擎。
- `vessels/src/propulsion.rs`：依 crossfeed_tanks 分組、按存量比例扣油、計算耗盡邊界。
- `modules/src`：引擎背壓和阻力已集中，但尚無通用的模組運行狀態／資源需求。
- `vessels/src/checkpoint.rs`、`fleet-flight/src/{checkpoint,session}.rs`：保存／重播必須讀同一份零件状态。
- RCS／對接有歷史上的未合入工作：先查可取得的程式與設計，寫出相容接口。找不到時明確記錄；不假定已經存在，也不再建第二套單推進劑供應。

## 必須成立的設計

1. catalog 定義與 live 狀態分開。模組以零件內穩定 ID 識別，不依賴 Vec 下標作持久識別；同一零件能容納多個同類模組。定義／狀態型別不相符、重複 ID、缺漏必要狀態均明確拒絕。
2. PartGraph 仍是唯一 live 真相。模組狀態、資源、stage／點火映射在受控接口下修改；不得在 Fleet、renderer 或 lab 各存一份可變副本。分離／合併保留零件及模組身份。
3. 第一版質量資源用 kg：至少既有液體推進劑與單推進劑兩種。定義宣告資源種類／容量，實例保存存量，消耗者宣告需求。資源 ID 不可變成任意未驗證字串。電力等非質量資源只說明擴充方式，本輪不實作。
4. 每個資源池是該資源可通行連接上的可達油箱；跨船供應禁止。明確定義 connection／part 的 crossfeed 對各資源的作用，保留舊液體供油語義。
5. 第一版引擎各消耗一種資源，不實作液氧／燃料混合比。多個消耗者共享池時，以穩定順序加總需求並共同求耗盡時間，不能逐引擎先扣完而令後者吃虧。部分重疊池若不能共同求解，必須在配置驗證時拒絕並記錄限制，不能算錯後繼續。
6. 資源不足是合法遊戲狀態：限制工作時間／輸出並產生熄火結果。NaN、無限、負存量、超容量、非法流率及非法狀態才是錯誤。不得用 clamp 掩蓋它們。
7. 模組求值與提交狀態分開。Dopri 試算 stage／被拒絕的步不能消耗資源或展開傘；只有接受的模擬時間推進狀態。orbit／bubble／ground 共用規則，不能按 render frame 更新。
8. 資源質量進入總質量、質心與慣量；沿用當前零件質量分布假設。消耗後更新、分離及合併的動量檢查限定在相應條件，不能把耗油過程誤當封閉系統。
9. 能改變施力的模組狀態須參與 rails blocker／切段／事件時間。展開降落傘的船在有空氣且會受力時不能走真空 rails；真空與大氣入口亦須有明確處理。

## 第一個有狀態的模組：降落傘

- 最小狀態：收起、待部署、半開、全開、切斷；指定合法轉移、壓力／動壓／高度條件、展開時間。重複命令語義必須明確，非法轉移不能默默忽略。
- 參數在 catalog：面積、阻力係數、部署條件與時間；本輪不加入撕裂、熱或布料求解。
- 傘作用於該零件位置，輸出力與作用點；記錄第一版如何處理力矩。不得假裝已有完整氣動姿態耦合。最小驗收可使用居中傘和對稱傘，任何暫不支持配置需拒絕或明確限定。
- lab 用簡單幾何顯示不同展開狀態，HUD 顯示模組 ID／狀態、動壓、資源／質量、owner、rails 原因。命令經正式模擬接口進入，能錄放，不能只有 GUI 直接改字段。
- 单推進劑消耗可用 lab 測試引擎證明，完整 RCS 分配器不在範圍。

## 交付順序

1. 提交具體資料型別／接口／狀態轉移表、RCS 相容核對、craft 格式決策與影響表，先供審查。
2. 資源核心與既有液體引擎迁移；比較無新模組的代表飛行輸出，差異需查明和量測。
3. 模組狀態、降落傘、Fleet owner 接線、lab、checkpoint／journal。
4. 文件、完整驗收操作和檢查結果；主遊戲啟用新功能在使用者 lab 驗收後才決定。因共享核心必需的舊功能接線須保持可編譯、可操作。

## 數值／行為驗收

- 舊液體推進劑的推力、流率、耗盡、背壓與 crossfeed 保持既有門檻；穩定迭代順序，不因容器換型別擾動結果。
- 兩種資源互不供應；封閉連接／分離後斷供；合併後依合法連接供應；共享池沒有超額消耗，最後不足一個步長時輸出與扣量一致。
- 同零件多模組不串狀態；身份和存量在 split／join／checkpoint 後保留；損壞資源／模組配置拒絕。
- 降落傘在不同 delta、paused、warp、owner 交接下按模擬時間展開；真空無阻力，空氣中阻力對相對氣流做負功；不得用終端速度一個數字代替時序覆蓋。
- 半開及全開中保存／還原後續跑與不中斷參考一致；錄放包含命令、狀態轉移、資源與輸出摘要。固定 seed 案例失败能單獨重跑。
- 純重構先做前後對照；新增降落傘行為另列，不要求它與真空舊船相同。不得放寬既有 golden 門檻。

## 使用者視窗驗收

提供 lab 一鍵預置：舊火箭、雙資源消耗、單傘返回、對稱雙傘分離。無需先手飛到起點。
使用者能操作部署／切斷、分離／切船、存讀檔、錄放，觀察返回減速、展開過程與狀態保留。列出按鍵、命令及預期現象，實際驗收前不標成已完成。

## 不在範圍

完整 RCS／對接、電力／ISRU、混合比、燃料優先級編輯器、熱／傘破壞、正式動畫、通用動態插件系統、ECS 重寫、全部舊 lab 模型淘汰、存檔跨版本自動遷移。
