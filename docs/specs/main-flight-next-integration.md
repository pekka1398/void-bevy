# 主遊戲繪圖框架、熱系統與 Solar scenery

2026-10-05，使用者授權直接在 master，由主 agent 獨立實作，不使用子 agent。
共用架構與驗證規則引用 ../../AGENTS.md。順序為繪圖框架、熱系統、scenery。

## 繪圖框架

四種 orbit core FrameSpec：質心、天體慣性、天體地表、雙體旋轉。主遊戲提供模式與
天體／雙體選擇、HUD。所有路徑按樣本自己的時間換框架，當下標籤及相機保持一致。
選擇寫入 checkpoint／journal；物理積分框架不隨繪圖選擇改變。不可由 renderer 推進
物理或偷偷改參考天體。測試地表固定點、快取倒退、存讀、錄放與物理不變。

## 熱系統

沿用 aero 熱模型：表皮／核心、氣流加熱、輻射、內部與相連零件傳熱、有限燒蝕。
定義與狀態歸入 PartGraph 穩定模組，燒蝕材料為有質量資源。trial 與觀察純讀，接受步
才提交溫度／資源並更新 owner 質量與慣量。提供防熱盾與主遊戲再入驗收入口、HUD
溫度／材料／失效資訊。核對 owner 交接、分離／對接、存讀／錄放、rails 邊界與能量。
不把完整撞擊／碎裂系統混入本輪；熱失效須明確呈現且不能繼續提供失效模組能力。

## Solar scenery

審查既有 work/solar-scenery 未提交成果，保留原 worktree；按接口採入 master。
主遊戲啟用同世界各天體外觀／LOD 地形／多大氣，具有可到達的觀察與驗收入口，
存檔／錄放保存世界配置。不能僅保留 example。光學與物理大氣分開，地形與碰撞
共用取樣器，GPU 資產／背景 task 在重建時有明確 ownership。第一輪可辨識外觀
不宣稱十顆天體已達到地球的細緻美術程度。
