# 主遊戲只有一個入口

## 目標

主遊戲就是一個遊戲：直接執行就進入正常的世界，不再靠一堆命令列參數切換成各種測試場景。

要測特定情境（再入、濺落、軌道對接等），用遊戲內的同一套機制把船放到想要的狀態，不另做世界（AGENTS.md 第 8 條）。

在 [清除舊 TS 遺留](remove-ts-legacy.md) 完成後才開始。

## 背景

2026-10-10 盤點時發現，每做一個功能，主遊戲的入口就多一種模式。現在 `fleet_game.rs` 認得 41 個命令列參數，而且很多參數互相排斥，靠一堆 `assert` 檢查組合（例如 `--rendezvous` 不能和 `--load` 一起用）。`--aircraft` 甚至會換成另一個平坦的跑道世界。

遊戲狀態全部放在一個叫 `Lab` 的物件裡（33 個欄位，被引用 568 次），模式開關、UI、相機、地圖、存檔、錄放、效能分析都混在一起。

## 範圍

### 1. 移除測試場景參數和寫死的案例

移除這些參數，以及只為它們服務的程式碼：

- 起始場景：`--rover`、`--aircraft`、`--reentry`、`--rendezvous`、`--splashdown`、`--water-speed`、`--water-tilt`、`--water-entry-angle`、`--cinder-site`、`--ares-site`、`--vesper-site`、`--ares-overview`、`--stellar-fixture`、`--stellar-neighborhood`、`--two-atmospheres`
- 換世界：`--planet`、`--terrain`、`--body`、`--vacuum`、`--world`、`--export-world`
- 寫死的驗收案例：`WATER_REVIEW_CASES`、各種 `*_fixture`、`aircraft_acceptance_planet` 等

### 2. 保留的入口

| 參數 | 用途 |
|---|---|
| （無參數） | 正常的主遊戲 |
| `--load <存檔>` | 從存檔開始 |
| `--record` / `--replay` / `--verify` | 錄下操作和重播，出問題時可以事後重現（AGENTS.md 第 1 條） |
| `--craft <檔案>` | 指定要飛的船。等遊戲內的 Workshop 做好，再看要不要拿掉 |
| `--recover-recording` | 修復中斷的錄影 |

效能分析相關的參數（`--profile`、`--render-profile`、`--render-benchmark`、`--benchmark-*`）見「要決定的事」。

說明文字（`--help`）跟著精簡。

### 3. 用一套機制取代測試場景

在遊戲內的 DEV 面板加一個「放置船」功能：選天體，再設定高度（或地面位置）、速度、姿態，就把目前的船放到那個狀態。再入、濺落、軌道、地面、別的恆星系，都用這同一個功能做到。

世界本身不變，只改船的狀態。放好之後可以用 F6 存檔，下次用 `--load` 直接回到那個情境。

飛機、車輛這類「換一艘船」的需求，靠 `--craft` 選船解決，不再為它們換世界。

### 4. 拆開 `Lab`

- 改掉 `Lab` 這個名字。
- 按用途拆成幾個獨立的 Bevy resource，例如飛行模擬、相機與視角、地圖繪製、錄放、UI 狀態。怎麼拆由負責的 agent 判斷，原則是同一類的東西放在一起，不再有一個什麼都裝的物件。
- 移除 `run(main_game: bool)` 的參數，現在只剩主遊戲一個呼叫者。

### 5. 修掉 fallback（AGENTS.md 第 1 條）

- `tiles.rs`：讀不到 CPU 核心數時默默用 4，背景工作數又跟著核心數翻倍。改成固定上限。
- `scenery/clouds.rs`：自己開執行緒，數量也要有固定上限。
- `terrain`：呼叫者沒給解析度時默默用 0.25 m 或 1 m。改成必須明確給。
- 存檔預設寫到已經不存在的 `lab-log/`。改成明確的存檔位置。

### 6. 測試

刪掉只為了被移除的模式而存在的測試，以及檢查「拒絕舊版本存檔」的測試。`fleet_game.rs` 裡約 1250 行的測試一起整理，只留確認主遊戲基本流程的幾個。

## 完成條件

- 直接執行 `void-app`，不帶任何參數，就是正常的主遊戲。
- 參數只剩上面「保留的入口」那幾個。
- 我能用 DEV 的「放置船」做出再入、濺落、在軌道上和另一艘船靠近這幾種情境，存檔後再讀回來。
- 遊戲狀態不再集中在單一物件裡。

## 要決定的事

- **效能分析參數要不要留？** `--profile`、`--render-profile`、`--render-benchmark`、`--benchmark-*` 是量效能用的。可以全部留著、精簡成一個，或者全部移除，需要時再加。
- **對接情境**：要兩艘船在軌道上靠近，「放置船」只能放一艘。可以先放一艘、切換到另一艘再放，或者乾脆讓「放置船」可以放在目標船附近。由實作時再跟我確認。
